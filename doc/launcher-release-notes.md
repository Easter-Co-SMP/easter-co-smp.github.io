# Easter Company launcher 1.0.22

Three corners of the interface that were too small for their own contents, all on a small window.

- **The drawing palette fits above the bar.** The launcher's smallest window is 800x600, and at that size the drawing palette's panel ran under the launcher's own progress bar: some of the tools and both colour controls sat below the window's edge, out of reach before a single message was on screen and further out of reach once one was. The panel is now measured against the first thing under it — the chart's footer or the bar — and scrolls inside the room that is left, so every tool and both colour controls can be reached. A full-size window is untouched.
- **Draw follows the window's width.** Where the palette sits was decided when the map loaded, so a window that started narrow and was then widened left the palette over the edge of the map key, where a click opened Draw instead of the key, and a window that started wide put it in the wrong place after narrowing. It now reads its position from the width the window is at, in both directions, on the website as well as in the launcher.
- **The account window has no dead scrollbar.** At the same 800x600 minimum the three-line wrong-account refusal left the account window showing a scrollbar with nothing to scroll, over space that was off screen anyway. Those twelve pixels are gone and every element stays exactly where it was drawn. On a window smaller than the launcher allows — a browser at phone width, or a future smaller minimum — the same refusal is now scrolled into view in full instead of being cut off at the window's edge, with Sign in and Forgot your password below it in the order a refusal is read.

Everything from 1.0.21 and before is unchanged: one name for signing in, the identity-conflict stop that explains itself, a failure notice that reserves its own room on every page, sign-in messages with an action per cause and no provider codes, the redacted `signin.log` and `install.log`, the verified-email picker and the twelve wiki guides.

Validation covers Node and Python unit tests, the browser suite against a local preview, the drawing suite and Electron journeys through the real main process, plus new assertions for all three fixes at 1440, 800 and 390 — each with a negative control, so the tests fail the way the defects failed rather than merely changing a number. A fourth round of independent frontend review ran against this tree before publishing and confirmed all six findings from the previous round closed, with no regressions. No real Microsoft approval was exercised here; the sign-in chain is proven against injected Microsoft, Xbox Live and Minecraft answers and the provider endpoints were probed with unauthenticated requests only. If something still refuses, `signin.log` names the sign-in step and `install.log` names the install failure.
