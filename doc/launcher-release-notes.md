# Easter Company launcher 1.0.21

The launcher's messages now read like something written for you, and nothing sits underneath them.

- **One name for signing in.** "Link Microsoft Account", "Login with Microsoft Account" and "Sign in with Microsoft" were the same action under three names, sometimes on the same screen. It is **Sign in with Microsoft** everywhere now: the hero button, the sticky bar, the sign-in window and the website's setup instructions. The button inside the Microsoft sign-in window says **Open the Microsoft page**, because that is exactly what it does.
- **The wrong-account stop explains itself.** If the Microsoft account you sign in with belongs to a *different* Easter Company account, the sign-in window now says so in three lines: what happened, that nothing on your account has changed, and what to do next — close the window first, then open your profile and choose Switch Account or Add account. Before, it used a phrase ("the linked account") that only made sense if you already knew what the conflict was.
- **Nothing sits under a message.** The failure notice reserves its own room now on the wiki and the map, not just the home page. It no longer covers the wiki menu, the guide heading, the search box on a phone, the map's key summary, its zoom controls, the compass or the drawing palette.
- **Sign-in messages say what to do.** The account that may not play now points at the likely cause — the wrong Microsoft account — instead of telling you to check something. Every connection failure reads the same way. And each Xbox cause carries its own instruction rather than a shared "try again": create an Xbox profile, finish age verification, or ask your Microsoft Family organiser to approve Minecraft.
- **No status codes on screen, and a record when something fails.** Install and update failures no longer print an HTTP number at you. Each one is written as a single redacted line to `install.log`, beside `signin.log` in the launcher's data folder, with the same cap and the same rules: no tokens, no addresses, no message bodies.

Everything from 1.0.20 and 1.0.19 is unchanged: the identity-conflict stop, one visible surface per failure with a message that waits behind a dialog, the step-by-step sign-in diagnostics and the redacted `signin.log`, the verified-email picker, and the twelve wiki guides.

Validation covers Node and Python unit tests, the browser suite against a local preview, the drawing suite, and Electron journeys through the real main process — including the identity-conflict journey that drives the real preload and asserts the signed-in account cannot change, and new tests that drive five install and update failures against the real modules and check both what the player reads and what the log records. Three rounds of independent frontend review ran against this release line; the last two each found real defects that were fixed before publishing, including a silent Easter Company account switch and a failure message that could not be read or dismissed. No real Microsoft approval was exercised; the sign-in chain is proven against injected Microsoft, Xbox Live and Minecraft answers, and the provider endpoints were probed with unauthenticated requests only. If anything still refuses, `signin.log` names the step and `install.log` names the install failure.
